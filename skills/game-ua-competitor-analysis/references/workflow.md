# 任务、接入、阶段划分、采集与归档

按当前用户授权和范围使用；案例与历史默认值不构成未来任务的事实或权限。

## 1. 目的与最终交付物

竞品分析要回答五个问题：

1. 产品实际在卖什么，广告又用什么理由吸引人？
2. 从开投到分析截止日，投放和素材更新经历了什么变化？
3. 每个阶段主要制作什么形式、什么主题、什么卖点的素材？
4. 单条素材怎样吸引注意、承接兴趣、展示收益并推动进入？
5. 哪些结构可以复用，哪些问题值得优化；不同产品为什么采用不同更新方式？

最终交付由三部分组成：

| 交付物 | 承担的内容 | 推荐组织方式 |
|---|---|---|
| 总览报告 | 产品定位、目标用户、推广节奏、阶段创意逻辑、跨产品结论 | 一个现有腾讯文档承载，面向汇报 |
| 素材分析表 | 每阶段、每图片、每视频的具体证据与买量分析 | 一个产品一个腾讯表格，不同阶段分 Sheet |
| 素材归档 | 下载原图、原视频，与分析行一一对应 | 产品文件夹→阶段文件夹→图片/视频及必要分类 |

不在总览中堆放数百条媒体和长篇逐条分析；不为每条视频另建一个腾讯文档。总览负责讲清判断，素材表负责提供证据，归档负责保存原件。


## 2. 必须遵守的基本原则

### 2.1 证据先于判断

- 图片逐张看，视频完整看；封面、文件名和少量关键帧不能代替完整观看。
- 关键帧、字幕、ASR 用于定位和复核，不能当作补写未出现情节的依据。
- “画面事实”“广告宣称”“分析推断”分开写。例如“素材称首个代言”不等于已外部核实首个代言事实。
- 人物、玩法、IP、版本等重要判断，应能回到具体素材、字幕、口播、署名或界面。
- 无法确认的人物身份，不凭脸相认；优先依据明确文字、署名和用户提供的识别信息。

### 2.2 从买量逻辑分析，不停留在复述剧情

每一条重要描述都应进一步回答：它吸引什么人、调动什么情绪或欲望、降低什么理解门槛、承诺什么回报、后段如何承接。

例如，“老奶拿枪打怪”只是描述；“年龄反差先建立人物记忆，弱势身份和强火力形成逆袭，随后用搜到装备解释战力来源”才进入买量分析。

### 2.3 不用不存在的数据下效果结论

- “最多计划使用”是采集排序口径，不等于最佳转化、最高 ROI 或最高消耗。
- 无 CTR、CVR、CPA、留存、付费等数据时，不设置虚构的数据分析栏目，不照搬参考图里的指标。
- 可写“这一结构的创意作用是……”“可能承接……动机”；不写“因此转化更高”“该阶段验证成功”。
- 样本构成仅代表所采集样本。例如“10 条中 8 条使用 KOL 资产”不能扩写成“全量投放 80% 都是 KOL”。

### 2.4 阶段有交叠，不能硬凑发展史

新方向出现，不代表旧方向立即消失；首次试探，不等于已经成为主导；投放高低变化，也不一定对应创意策略换轨。

### 2.5 保护文件与账号

- 共享盘只在获准的目标范围内新增和整理；其他已有文件不得删除、移动、覆盖或改名。
- 优先复用现有总览与产品表格，不制造临时文档污染账号。
- 修改前保留可回退记录；核对素材行、预览、附件和链接的对应关系。
- 认证密钥不写入报告、项目目录、日志、截图或版本控制，不展示完整值。


## 3. 接单：先确定任务口径

执行前形成一份内部任务卡，不必把这些管理字段写进领导看的报告。

| 项目 | 必须明确的内容 |
|---|---|
| 产品 | 准确名称、图标、目标版本、所属平台/渠道；必要时保留产品 ID 用于内部匹配 |
| 范围 | 全生命周期，还是指定的一个/几个阶段 |
| 截止日 | 本次分析统计到哪一天，不能把截图日期或“至今”含混处理 |
| 素材口径 | 图片/视频分别采集多少、按何种排序、是否勾选新增素材、媒体是否不限 |
| 输出位置 | 总览链接、已有素材表链接、共享盘产品目录和阶段目录 |
| 文件保护 | 可新增的目录、不得触碰的已有内容 |
| 命名参照 | 现有阶段和文件的格式，编号是否分阶段重置 |
| 权限与媒体 | 谁需要查看，能否上传原视频，使用何种预览方式 |

以下情况必须先澄清，不猜：产品同名但版本不同、名称/URL/Key 为空或占位、查询日期与开投时间冲突、目标位置无法唯一确定。

日期处理示例：文件夹年份与开投时间冲突时，确认真实筛选日期；用户要求保留旧目录名，则保留并内部记录真实日期，不擅自修正或猜测。


## 4. 数据源与 MCP 接入

以ADX等投放情报服务为例。接入配置属于执行准备，不属于竞品报告正文。

1. 优先检查当前平台已配置的服务，避免重复安装。
2. 如需配置，采用平台原生、用户级 MCP 配置；保留其他服务，只做必要修改。
3. 服务名、传输方式和URL使用用户提供的实际值；可用服务优先复用，不虚构接口。
4. 地址缺少 `/mcp` 时补一次，已有后缀不重复拼接。
5. Bearer Key 优先放安全凭据存储或用户环境变量。实际发送头为 `Authorization: Bearer <用户提供的密钥>`，不额外添加引号、换行或第二个 Bearer。
6. 用 `initialize` 和 `tools/list` 验证该服务，记录可用工具、错误信息与是否需要重启会话。
7. 验证报告只列该服务实际返回的工具名，不混入其他 MCP 服务工具。
8. 对用户说明配置位置、认证方式、验证结果和必要的重启事项，密钥全部脱敏。

不要为方便接入另建本地代理；不要把密钥硬编码到分析脚本或共享盘文件中。新的数据源接入也沿用这些保护原则。


## 5. 确认目标产品

按产品名搜索后，逐项比对名称、图标、平台标记、版本、开投时间和页面信息。例如微信小游戏版本不能直接用同名原生手游或其他渠道版本替代。

在内部台账保存产品 ID、来源页和查询口径，便于复现；对外报告只保留分析需要的信息。类似“微信小游戏·ADX 产品 ID·85 条视频·4 个归档阶段”不应成为产品分析开头。

产品定位要把两层分开：

- **产品本体定位**：实际题材、核心玩法、体验与成长回报。
- **广告获客表达**：广告用什么入口吸引人，是否用了假设玩法、夸张演绎、经典 IP、AI 或 KOL。

副玩法广告不能自动证明本体拥有相应功能，但它仍然是买量策略的重要证据。


## 6. 获取趋势并划分阶段

### 6.1 趋势范围

从首次开投到本次确定的截止日，获取完整投放趋势。优先同时观察：

- 投放计划数：观察投放规模与密度的变化。
- 在投/投放素材数：观察素材池规模。
- 新增素材数：观察上新频率与创意供给。

平台字段含义以实际返回为准。阶段均值、峰值、新增占比等可以用于内部判断，不必把趋势图中已有的数值再逐项堆进报告。

### 6.2 划分依据

重点找开投爬坡、明显冲峰、高位波动、再度放量、回落调整、平静期、低位长尾等变化。边界参考持续变化，避免一日尖峰就另切一个阶段，也避免按自然月平均切。

通用流程：

1. 先看全周期趋势，标出明显峰谷与结构变化。
2. 给出候选日期区间。
3. 回看候选区间内素材，观察上新节奏和内容是否有变化。
4. 确定阶段日期、投放状态、主要创意动作。
5. 检查日期连续、无无意重叠、无遗漏。

若只分析指定阶段，趋势仍要查看前后背景，但逐条素材不擅自扩展到其他阶段。

### 6.3 分开记录“投放阶段”和“创意变化”

| 维度 | 判断问题 |
|---|---|
| 投放阶段 | 计划/素材曲线什么时候放量、回落、维持？ |
| 素材迭代 | 在这个时间窗里，主要换了人物、主题、玩法、入口、版本，还是只换元素？ |

两者可以相关，但不能强行一一对应。《案例C》可有多个投放强弱时间窗，创意上仍主要沿用 A 面变体＋数字门 B 面变体。《案例D》某些时间窗横跨多个版本，不能把一个 ADX 阶段直接等同一个官方赛季。


## 7. 分阶段筛选素材

默认采集示例（用户指定的口径优先）：

1. 选择已核对的目标产品。
2. 设置该阶段准确的起止日期。
3. **媒体不限，不筛选媒体。**
4. **勾选/点击新增素材。**
5. 排序选择 **最多计划使用**，不是最近出现、出现次数或其他指标。
6. 素材类型先选视频，取该口径下前 10 条。
7. 素材类型切换为图片，取该口径下前 10 张。
8. 每次切换类型/日期后复核筛选是否仍然生效。

上述10＋10是可调整的采样默认值，不是所有竞品分析的固定样本量。若后续明确扩大范围，或已有归档多于 10 条，应按确认范围逐条覆盖，不擅自删减成 10 条。

执行边界：

- 不足 10 条时如实记录，不用低排名、跨阶段或另一产品素材偷偷补满。
- 需要候补时记录原排名和替换原因；是否放宽口径由任务要求决定。
- 横竖版、同母版变体在原排名中可以分别保留，但分析时注明其关系，不当成两个独立卖点。
- 相同文件重复下载与“同母版不同变体”分开处理。
- 对明显出现其他品牌、其他游戏的素材保留事实说明。不要误当成本体玩法，也不要仅因不像本体就把其获客价值一概排除。


## 8. 下载、归档与素材台账

### 8.1 目录结构

沿用用户指定共享盘和已有规范。结构示意：

```text
竞品分析素材收集/
  产品名称/
    第1阶段（YYMMDD-YYMMDD）/
      图片/
      视频/                 # 若原目录已分A+B/单B或按卖点分类，则沿用
    第2阶段（YYMMDD-YYMMDD）/
```

原始文件优先保留完整画面、分辨率、音轨与原图质量。分析用帧图、ASR、脚本、缓存和校验文件放本地工作目录，避免把执行产物混入正式共享盘归档。

已有文件处理规则：先只读查看命名和结构；新增前查重；碰到同名文件不自动覆盖；用户没授权时，不对其他已有文件作任何整理动作。

### 8.2 命名

- 基本形式：`01 名称`，编号便于排序。
- 单独 B 面视频：名称正文不超过 10 个字。
- A+B 视频：`01 xxx+xxx`，前半概括 A 的钩子，后半概括 B 的主要卖点。
- 图片：用“主体＋动作/场景/主题”短命名。
- 横竖版本仅加必要区分，不重复写长剧情。
- 旧编号、原名、素材 UID 与最终短名在内部保留映射，不能因重命名错配附件。

示例：`01 老奶机甲清场`、`02 泡面求援+强装搜打撤`、`03 抽签落水+机甲撤离`。不要把一整段分析塞进名字。

### 8.3 内部台账

建议一条素材一行，至少记录：产品/版本、阶段/日期、素材 UID、类型、原榜排名、筛选口径、原名、短名、本地与共享盘路径、来源页、时长/分辨率、预览文件、云表格/Sheet/行号、附件对应关系、观看复核状态。重要结论另记时间点和文字证据。

这些字段服务追溯，不要求全部出现在汇报表中。
