# 报告结构、图表、排版与媒体交付

按当前用户授权和范围使用；案例与历史默认值不构成未来任务的事实或权限。

## 14. 总览报告的推荐框架（遵循用户当前格式约定）

```text
游戏竞品分析（产品数量与题材按任务调整）

1. 产品A
   产品定位
   目标用户
   推广节奏
     ADX真实投放趋势图
     素材更新与内容迭代说明
   素材分析
     本产品阶段节奏图
     第1阶段 日期：阶段说明＋对应Sheet链接
     第2阶段 日期：阶段说明＋对应Sheet链接
     ……

2. 产品B
   同上
3. 产品C
   同上
4. 产品D
   同上

综合分析
   所选产品的对比与异同
   同题材共同买量打法
   后续竞品素材应该怎么做
```

目录保持这个层级，所选产品、综合分析、各阶段都要能导航。不把每条素材名做成左侧目录标题，不出现空标题。图片/视频/卖点分类在素材表内部展示。

### 14.1 产品定位

用简短段落写题材、玩法循环、主要体验和差异。广告有fake表达时，产品定位不随广告演示任意改变。

### 14.2 目标用户

优先按动机分析：囤货安全感、随机摸宝、成长爽感、恐怖氛围、角色反差、社交家园、经典IP熟悉感、明星认知、老玩家回归等。没有用户数据时不硬写精准年龄、性别或收入比例；广告想吸引的人与实际用户画像也要区分。

### 14.3 推广节奏

必须贴 ADX 真实趋势，并说明素材何时密集上新、何时复用、主题怎样扩展、旧母版如何延续。不重复逐行列出图里已有的峰值和均值，不把趋势分析简化成“先高后低”。

### 14.4 综合分析

产品对比建议用表格，列“更新主线、主要拓量方式、稳定母版、变化变量、可复用做法”。共同点不能只有“都有丧尸”：应总结威胁、成长、安全感、熟悉入口、主题系列和行动回报等机制。最后给出可执行的素材生产/测试建议，区分观察结论与后续待验证假设。


## 15. 两种趋势图必须区分

| 图 | 作用 | 制作要求 |
|---|---|---|
| ADX投放趋势图 | 展示实际投放变化 | 使用真实来源，日期清晰，图片本身可见，不只有来源小字 |
| 素材阶段节奏图 | 用一张图解释各阶段主要创意动作 | 一个阶段一个点＋简短文案＋对应阶段真实素材图 |

阶段节奏图放在每个产品“素材分析”开头：

- 曲线按大致投放节奏绘制；若用阶段日均计划归一化，明确是相对示意。
- 一个阶段一个点，不伪装成逐日真实趋势；阶段等距也要说明。
- 每阶段说明不超过 10 个字，能读出主要动作。
- 每阶段配真实图片或视频帧；必要时同阶段两图体现双线。
- 画面来自对应阶段，避免为好看而跨阶段错配。
- 风格匹配游戏：废土卡通、幽紫怪谈、战术HUD、写实末日等；保证汇报可读。
- 标题、标签不能遮挡或溢出，图文留出间距；颜色/字号在文档实际宽度下检查。

相对示意曲线不能取代 ADX 真实图；两张图分别回答“投放怎么变”与“创意怎么变”。


## 16. 素材表格式

每个产品一份腾讯表格，每阶段一个 Sheet；阶段内依次图片、A+B、单B，再按卖点分组。统一 10 列可采用：

| 列 | 栏目 |
|---|---|
| A | 素材名称 |
| B | 画面预览 |
| C | 视频预览 |
| D | 图片内容／HOOK |
| E | A+B衔接 |
| F | 构图／核心卖点与亮点 |
| G | 内容架构 |
| H | 转化设计 |
| I | 可复用点 |
| J | 优化点 |

图片行在 B 贴原图，C 写“—”；D 写图片内容，F 分析构图与卖点，不硬填时间轴或A/B衔接。视频行 B 贴真实画面，C 对应完整视频，D—J 逐项分析。无适用内容写“—”，不写无意义凑字。

表头以上设置阶段标题和五项阶段说明；标题/表头/分类条有明确视觉层级。阶段标题与日期可见，适当冻结表头和识别列，长文换行，列宽/行高适配内容。

可用深色表头、浅色交替底色、淡黄色核心卖点列，但颜色只服务阅读。关键字通过**单元格内的富文本片段**加粗/标红，不能把整个单元格全部加粗或全红。


## 17. 文字与排版规范

1. 面向汇报写结论与理由，去掉过程交代和自我辩解。
2. 不在正文加入无分析价值的产品ID、归档数量、技术接口和“分析范围与阅读口径”等管理段落。
3. 不展示“前期素材样本未归档”“不是停更”之类与判断无关的执行痕迹。
4. 数据缺口影响结论时，简洁、诚实说明判断边界，不能为美观掩盖关键限制。
5. 避免单元格长篇复杂句；每句提供一个判断或证据，减少同义重复。
6. 重点可采用红字、加粗、黄色底色等，不必每处都叠加三种。子表仅强调词语或短句。
7. 小标题足够醒目，标题显示完整，正文两侧留白充足。
8. 分页文档中标题与后文保持同页；表头不孤悬，重要单条分析不跨页断裂。连续模式也要检查阅读顺序。
9. 全文检查图像加载、表格宽度、文字裁切、异常空行、空标题和目录缺项。
10. 不自行改掉用户已调整的标题、编号、视图和排版偏好；基于现状局部修订。


## 18. 视频交付、权限与卡顿处理

### 18.1 优先媒体方案

原视频上传到现有产品表格的原生附件/视频预览位置，与素材行一一对应。具体界面可能以内联预览或点击附件打开，须实际验证；不把“接口返回成功”当成“用户已能观看”。

已验证可用的原视频上传交付，不应静默退回只有封面、临时URL或每条视频一个文档。

### 18.2 不能直接充当长期入口的地址

- 历史任务中曾发现数据源视频直链在短时间后过期，不适合作为长期汇报入口；以后也应实际检查链接有效性。
- 素材详情页可能要求 ADX 登录，不能当所有领导都能打开的公开预览。
- `\\fs...` 共享盘路径用于公司网络内归档，不等于腾讯文档可访问的公开视频URL。
- 本地磁盘路径更不能直接给远程读者作为媒体预览地址。

确实无法原生上传时，再与用户确认稳定存储或“预览图＋可长期访问视频链接”的替代方案。先检验原生能力，不先造大量预览文档。

### 18.3 权限

新建或迁移后测试实际查看权限。只有当前任务明确授权时，才对指定文件设置“获得链接的人可查看、不可编辑”；不能把历史授权推广为未来默认公开。不可编辑也不等于不可外传，分享方式须按用户要求执行。

### 18.4 卡顿与打不开的排查顺序

1. 判断是总览慢、某个产品表慢，还是子文档根本打不开。
2. 先查登录拦截、私密权限、链接错误和资源加载失败。
3. 再查大量媒体、附件、超长表格导致的体量与渲染压力。
4. 核对视频是否真的上传、是否错链、是否只是短期URL。
5. 总览保持轻量：分析摘要＋真实趋势＋阶段图＋阶段链接；逐条媒体下沉到产品表格的阶段Sheet。
6. 模拟读者沿“总览→产品阶段→单条视频”完整打开一遍。

“打不开”不一定是性能问题。历史任务曾复现子文档私密状态导致的登录拦截，因此权限与性能必须分别确认。


## 19. 修改与发布流程

1. 读现有文档与素材表，确认当前标题、结构、链接和用户已做的改动。
2. 保存修改前快照及素材—行—媒体映射。
3. 根据原素材形成修订稿，先改结论与分类，再做局部排版和强调。
4. 优先在原表原行更新文字，保护图片锚点与视频附件；非必要不插删整行整列。
5. 如需改变分组位置，先完整迁移该行的文字、图片与附件，再核对映射，不能只移动文字。
6. 同步修改阶段说明、逐条分析、总览推广节奏、综合分析和阶段图，避免互相矛盾。
7. 云端重新读取核对保存结果；对重要页面实际打开并截图检查。
8. 只清理明确属于本次任务的冗余文档。用户要求删除时先核对清单，优先可恢复删除；不要清空回收站或误删原总览/四份正式表格。
9. 完成后报告更新范围、入口链接、核验结果及真正未解决的问题，不把尝试动作说成已完成。
