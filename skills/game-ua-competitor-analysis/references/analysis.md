# 逐图、逐视频与阶段买量分析

按当前用户授权和范围使用；案例与历史默认值不构成未来任务的事实或权限。

## 9. 图片逐张分析

每个阶段先分析图片，再分析视频。图片不仅要汇总数量和类型，**每张都要贴图并单独分析**。

推荐观察维度：

| 维度 | 要看什么 |
|---|---|
| 图片类型 | 人物介绍、群像、房车/庇护所、逃生探索、玩法/装备、KOL推荐、版本/IP等 |
| 画面内容 | 主体、动作、环境、道具、怪物、文案和利益点 |
| 视觉钩子 | 年龄/身份/力量反差、巨物压迫、危险与暖屋、熟悉人物、稀有奖励 |
| 核心卖点 | 安全感、角色收藏、强装成长、探索收益、版本新鲜感、KOL推荐等 |
| 构图与信息层级 | 大小、冷暖、明暗、视线方向，人物/威胁/奖励能否一眼读懂 |
| 转化设计 | 是否给明确目标、福利、行动或可获得回报 |
| 复用与优化 | 哪个母版可保持，哪个具体信息应补、删、放大或对齐 |

阶段图片总结至少说明：哪类占主导、什么主题反复出现、与上一阶段相比如何变化。数量结论必须有分母，并限定在所采集样本内。

不要按文件名认内容，不把角色立绘全部当一般人物；需观察其是否已变成 KOL 推荐、角色主题延展、古文明探索或版本主视觉。


## 10. 视频完整观看与分类

### 10.1 先定形式，再定卖点

第一层：A+B、单独 B、其他需要说明的结构。A/B 不是“真人/游戏”的简单二分。

- A 通常承担吸睛、情绪、关系冲突、悬念、熟悉人物等入口功能，可以是真人、AI、动画、评论或口播。
- B 通常承担玩法、收益、成长、世界体验和进入理由的展示，可以是实录、演示或副玩法化内容。
- 单 B 也可以叠主播、KOL 口播与包框；不因有真人头像就强行判为 A+B。
- 连续游戏演出、动画预告、A/B 多次交替等要如实描述，不强套一次性 A→B。

第二层：在每个形式下，按核心卖点分组，同类放同一个表格/分组中，例如搜打撤、房车改装、囤货避难、人物反差、背包构筑、数字门、塔防守门、AI副玩法、版本/新种族等。

最终顺序：**产品→阶段→图片→视频A+B→视频单B→各自的卖点分类→逐条分析**。不跨阶段把同类素材混成一张“大杂烩”表。

### 10.2 完整观看要求

先完整观看，再标记：开头、核心转折、A/B 接点、B 的操作/成长链、结尾转化。时间点按实际记录，不凭时长推算；字幕与画面不一致时分别说明。

关键帧可帮助复核，但容易漏掉中段 KOL 署名、尾板、玩法改变与结算。人物资产还可能出现在 B 口播、包框、福利页和结尾，不能只检查前 3 秒。


## 11. 单条视频的标准分析字段

| 字段 | 必须回答的问题 | 写法要求 |
|---|---|---|
| 素材名称 | 是哪一条？ | 短名＋编号，符合A+B或单B规则 |
| 画面预览 | 用户能否直接认出素材？ | 贴真实画面，不用泛封面替代 |
| 视频预览 | 用户能否打开对应完整视频？ | 优先上传原视频到现有产品表格的原生附件/预览位置 |
| HOOK | 第一注意力来自哪里？ | 写具体画面/台词、冲突和观看动机，不只写“有反差” |
| A+B衔接 | 为什么从A切到B，兑现了什么？ | 标实际接点，判断同人物/同物件/同任务/同顾虑的连续性 |
| B面核心卖点与亮点 | 观众实际看到了何种收益？ | 写操作、选择、成长与反馈，区分实录、演示和广告宣称 |
| 内容架构 | 信息按什么顺序展开？ | 简短时间轴：问题→选择→反馈→结果，不重写完整脚本 |
| 转化设计 | 为什么继续看、点开或进入？ | 福利、挑战、失败纠错、成长向往、熟悉推荐、回归便利等 |
| 可复用点 | 哪个结构能迁移，保持什么变量？ | 机制或结构层面的结论，而不是照搬具体人脸、IP或画面 |
| 优化点 | 具体改哪里，解决什么问题？ | 可执行，针对本条；无效果数据时不写确定提升幅度 |

推荐精简展示：普通素材每字段 1—3 句；复杂衔接适量增加。内容有多少证据就分析多少，不为填满单元格编故事。

### 11.1 A+B衔接的判断层级

1. 同一物品：A 说要找八卦镜，B 立即展示双镜摆放。
2. 同一任务：A 缺药，B 搜药并用药解决问题。
3. 同一能力/结果：A 机甲解围，B 展示搜到、装配、使用机甲。
4. 同一顾虑：A 质疑假广告，B 展示启动入口和完整玩法。
5. 仅同题材：A 丧尸求援，B 另一个无关副本；题材一致但任务没有闭环。
6. 卖点脱节：A 承诺一种体验，B 没展示或切成另一种利益。

分析要指出具体接住和没接住的部分，不用“衔接流畅”一句带过。

### 11.2 转化不限于结尾按钮

完整目标、失败差一点、选择题、高价值物、即时变强、KOL 推荐、福利码、新版本身份、回归减负，都可能承担转化作用。没有下载尾板不代表没有进入动机；但不能把广告台词直接当作已兑现利益。

### 11.3 优化点要能执行

有效示例：第一次机甲掉落格停留更清楚；口播头像避开物品栏；A 点名道具后 B 第一帧就展示同款；保留一次低收益搜索解释随机性；补前贴救援的结果；减少重复规则，只留一个关键选择。

无效示例：“增强吸引力”“提升转化”“画面更好看”“节奏优化一下”。


## 12. KOL、经典IP、AI、fake的专项判断

| 类型 | 识别证据 | 分析重点 | 不能混写的事 |
|---|---|---|---|
| KOL/明星 | 明确署名、口播、自我介绍、宣传文案、用户提供的识别信息 | 熟悉感怎样进HOOK、B面、角色化、包框、福利和结尾 | 素材自称代言不等于外部核实合同；不能凭无文字人脸猜身份 |
| 经典IP借势 | 明确游戏封面、角色名、标题、菜单或典型规则 | 如何借已有认知降低理解成本，吸引泛游戏用户 | 借势不等于目标产品拥有该IP或对应正式玩法 |
| AI演绎 | 生成标识、可核实来源及具体画面特征 | 是否低成本扩人物/场景/冲突，怎样承接后段 | AI只是一种制作形式，不自动等于fake玩法 |
| fake/副玩法化 | 相对已核对本体玩法明显偏离，或已确认属于创意副玩法 | 用什么更轻的规则、选择和反馈拓人群 | 不能只因画风不同就断定fake；也不能因不是本体就排除买量分析 |

“末日/鬼新娘”是主题，“塔防/背包/数字门”是玩法结构，“AI/真人/动画”是制作或表现形式，“KOL/IP”是认知资产。分类时可以多轴标注，不把它们当互斥标签。

遇到另一游戏品牌或泛内容时，记录它在当前素材中的作用，同时保留归属边界：可以分析其入口结构，不能反推目标产品的正式功能、用户画像或版本历史。


## 13. 每阶段开头的标准说明

每个阶段 Sheet 开头都要详细说明“这一阶段主要做什么”，不能只留一句模糊总结。推荐固定五项：

1. **阶段主线**：一句话概括主要创意动作。
2. **图片**：主导类型、内容主题、典型构图及与上阶段变化。
3. **A+B**：主要 A 面形式/钩子，接什么 B，衔接依靠什么。
4. **单B**：主要机制、成长回报、玩法演示形式，是否有KOL口播等覆盖。
5. **迭代逻辑**：本阶段更新了什么、保留什么、可能服务什么获客动机，并列出必要的样本例外。

“为什么这样做”需建立在内容结构上，例如“固定老奶降低人物识别成本，更换任务提供新鲜感”；不要改写为无证据的内部决策或效果事实，如“团队验证老奶ROI最高，因此全面转向”。

总览内的阶段说明与子表同一口径，但更聚焦结论；不要把逐条细节全文复制到总览。
